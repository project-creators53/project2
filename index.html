リレーショナルデータベース（RDBMS）とは？

データを「行（レコード）」と「列（カラム）」で構成された「テーブル（表）」の形式で管理する仕組みです。 複数のテーブル同士を「主キー（PK）」と「外部キー（FK）」で関連付ける（リレーション）ことで、重複のない効率的なデータ管理が実現できます。

users テーブル (顧客情報)

親テーブル
id (PK) name (名前) age (年齢) city (都市)
PK (Primary Key / 主キー): 各行を一意に識別するための重複しないID。

orders テーブル (注文履歴)

子テーブル
order_id (PK) user_id (FK) item (商品名) price (金額)
FK (Foreign Key / 外部キー): 他のテーブルのPKを参照するID。これによりデータ同士が紐づきます。

インデックス（Index）による高速検索の仕組み

データ量が増えると、上から1行ずつ探す**「フルスキャン（全件検索）」**は時間がかかります。 **「インデックス（B-Treeなどの索引）」**を使うと、辞書を引くように目的のデータを爆速で探せます。

トランザクション & ACID特性

複数の処理を**「すべて成功させるか、すべて無効にするか（オール・オア・ナッシング）」**の単位として扱う仕組みがトランザクションです。銀行口座の送金処理などで不可欠です。

Atomicity (原子性)

処理が「全て実行される」か「全く実行されない」かのどちらか。中途半端な状態を残さない。

Consistency (一貫性)

データが不整合を起こさないルールを守る（例: 残高マイナス不可などの制約）。

Isolation (独立性)

同時実行される複数の処理が互いに干渉しないように隔離される。

Durability (永続性)

COMMITが完了した変更結果は、システム障害が起きても消えず永続化される。
